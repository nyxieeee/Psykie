# Psykie — User Stories and Acceptance Criteria

## Priorities
- **P0:** Security or launch blocker.
- **P1:** Core MVP.
- **P2:** Later enhancement.

## Epic A — Authentication and access control

### US-A01 — Register and sign in (P0)
As a user, I want to create an account and sign in securely so that I can access my workspace.

**Acceptance criteria**
- Supabase Auth handles registration, login, logout, and recovery.
- Invalid credentials produce a safe error.
- Profile initialization links to the authenticated user.
- Users cannot self-assign admin or other privileged roles.
- Credentials and tokens are not logged.

### US-A02 — Isolate private records (P0)
As a user, I want my records protected from other users so that private data remains private.

**Acceptance criteria**
- RLS is enabled on all exposed tables.
- User A cannot read/update/delete User B's rows by changing an ID.
- Insert/update policies prevent spoofing owner IDs.
- Storage access is protected by policies.
- Automated tests cover student, professional, and unauthorized access.

## Epic B — Student dashboard

### US-B01 — View personalized dashboard (P1)
As a student, I want to see subjects, assignments, exams, and deadlines so that I can plan study time.

**Acceptance criteria**
- Dashboard uses persisted Supabase records.
- Deadlines are ordered correctly and respect timezone settings.
- Loading, empty, and error states exist.
- Updates remain after refresh and login on another device.

### US-B02 — Manage academic schedule (P1)
As a student, I want to create/update subjects, assignments, and exams so that my plan stays current.

**Acceptance criteria**
- Authorized CRUD operations work.
- Required fields and dates are validated.
- Completion/archive state persists.
- Cross-user access is denied.

## Epic C — Mindy AI chat and history

### US-C01 — Ask Mindy an academic question (P1)
As a student, I want Mindy to explain psychology concepts and answer academic questions so that I can study effectively.

**Acceptance criteria**
- Requests go through a server-side Edge Function or trusted backend.
- Provider secrets are not included in the browser bundle.
- Output is clearly identified as AI-generated.
- Rate limits, input/output limits, and safe error states exist.
- The app does not claim that template output is live AI.

### US-C02 — Create and switch chats (P1)
As a user, I want multiple named conversations so that I can separate study topics.

**Acceptance criteria**
- User can create a chat and switch between owned chats.
- Session list shows title, last activity, and optional message count.
- The selected session loads its messages in chronological order.
- Session IDs are generated by the database or a collision-resistant UUID, not timestamp-only IDs.

### US-C03 — Persist AI chat history (P0 for history feature)
As a user, I want conversations and messages saved to my account so that I can revisit them after refresh or on another device.

**Acceptance criteria**
- Each session belongs to the authenticated user.
- User and assistant messages are persisted in Supabase.
- Reloading and signing in again restores the user's sessions.
- Sessions sort by `updated_at DESC`; messages use stable chronological ordering.
- RLS prevents cross-user session/message access.
- Failed AI calls preserve the user prompt and show a retryable error state.
- Deleting a session deletes or archives its messages according to a documented retention policy.
- Chat history has pagination for long conversations.
- The system does not store hidden chain-of-thought.

### US-C04 — Rename, archive, and delete chats (P1)
As a user, I want to organize and remove conversations so that my history stays useful.

**Acceptance criteria**
- Rename and archive actions update persistent metadata.
- Delete requires confirmation when destructive.
- Deletion behavior for messages and linked artifacts is consistent.
- Another user cannot modify the session by guessing its ID.

### US-C05 — Generate study material from chat (P2)
As a student, I want to turn a conversation into a quiz or flashcards so that I can practice what I learned.

**Acceptance criteria**
- User explicitly selects the action.
- Generated artifacts are previewed and editable before saving.
- Artifacts link back to the source chat where useful.
- AI output is validated against a defined schema.

## Epic D — Notes, quizzes, flashcards, and board review

### US-D01 — Summarize lecture notes (P1)
As a student, I want a lecture summary and key concepts so that I can review efficiently.

**Acceptance criteria**
- Supported files/types and size limits are documented.
- Uploads use private storage.
- Processing status and failure states are shown.
- Summary is linked to source material and can be edited before saving.

### US-D02 — Create and review flashcards (P1)
As a student, I want AI/manual flashcards and spaced repetition so that I can retain concepts.

**Acceptance criteria**
- Decks/cards persist in Supabase.
- Review ratings and timestamps are stored.
- Next-review time follows a documented algorithm.
- Users can edit/delete only their own cards.

### US-D03 — Take a board-review mock exam (P1)
As a student, I want topic quizzes and timed mock exams so that I can evaluate my knowledge.

**Acceptance criteria**
- Question source and generated/practice status are displayed.
- Timer, submission, scoring, and rationale behavior are deterministic.
- Attempts and topic-level performance persist.
- Results do not claim to predict official exam results.

## Epic E — Research assistant

### US-E01 — Search trusted research (P1)
As a student, I want results from trusted sources so that I can use credible academic material.

**Acceptance criteria**
- Search uses an approved source allowlist/API.
- Metadata and URLs are validated before display.
- Result cards show source, title, date, and DOI/identifier when available.
- Unverified results are omitted or clearly labeled.
- No citation is represented as verified merely because AI generated it.

### US-E02 — Summarize article and format APA citation (P1)
As a student, I want a sourced summary and APA citation so that I can understand and cite research.

**Acceptance criteria**
- Summary points link to retrieved source metadata when feasible.
- Citation formatting uses validated fields and never invents missing values.
- Copyright/access limitations are respected.
- The user can open the source.

### US-E03 — Understand methods and statistics (P1)
As a student, I want plain-language explanations of research methods and statistics so that I can interpret studies.

**Acceptance criteria**
- Explanations distinguish general education from interpretation of a specific study.
- Statistical assumptions and limitations are stated where relevant.
- Sources are included for claims that depend on external evidence.

## Epic F — Professional scheduling and client records

### US-F01 — Manage appointments (P1)
As a professional, I want to schedule, reschedule, cancel, and receive reminders so that my calendar is reliable.

**Acceptance criteria**
- Appointment start/end times and timezone are stored consistently.
- Conflicts are surfaced according to product policy.
- Reminder jobs are idempotent and avoid sensitive message content.
- Other professionals cannot access appointments without permission.

### US-F02 — Manage client profiles and session history (P0 before real data)
As a professional, I want secure client records and session history so that I can organize my work.

**Acceptance criteria**
- Access requires ownership or explicit care-team membership.
- RLS and trusted backend checks enforce authorization.
- Sensitive content is excluded from ordinary logs and analytics.
- Retention, deletion, export, backup, and audit policies are documented.

### US-F03 — Save a progress note (P0 before real data)
As a professional, I want to save a note linked to a client/session so that I can maintain documentation.

**Acceptance criteria**
- Only authorized professionals can read/write the note.
- Notes use private database/storage access.
- Audit metadata does not duplicate note content.
- Failed saves do not show false success.

## Epic G — Clinical reference tools

### US-G01 — Search diagnostic educational references (P1)
As a student or professional, I want searchable diagnostic-reference summaries so that I can learn about diagnostic concepts.

**Acceptance criteria**
- Each entry has source/version/review metadata.
- Content is original, licensed, or otherwise permitted.
- The UI explains that a checklist is not a diagnosis.
- DSM-5-TR content is not reproduced beyond authorized use.
- Qualified review and version history are available.

### US-G02 — Consult assessment and therapy resources (P2)
As a professional, I want reviewed assessment and intervention resources so that I can find appropriate materials.

**Acceptance criteria**
- Resources show source, intended use, review date, and limitations.
- Restricted test items are not exposed without permission.
- Scoring support is available only where licensing permits it.
- AI suggestions are not represented as validated clinical instruments.

## Epic H — Reliability

### US-H01 — Recover from errors (P1)
As a user, I want understandable errors and safe retry behavior so that I know whether an action succeeded.

**Acceptance criteria**
- Failed writes do not show success.
- Retries do not create duplicate records.
- Errors do not leak secrets or private content.
- Operational logs use sanitized metadata.

### US-H02 — Restore from backup (P0 before production)
As an administrator, I want tested backups and recovery procedures so that data can be restored.

**Acceptance criteria**
- Backup frequency and retention are documented.
- Restore is tested outside production.
- Recovery objectives are defined.
- Schema migrations are version controlled.

## Definition of Done

- Acceptance criteria verified by automated tests or documented manual test.
- Supabase migration and RLS policies reviewed.
- Cross-user authorization tests pass.
- Loading/empty/error/success states exist.
- Documentation and `.env.example` are updated.
- No secrets or real client data are committed.
